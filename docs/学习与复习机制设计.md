# 学习与复习机制设计

本文档描述当前词汇小程序的学习方法、答题反馈、错题机制和复习调度。

本文档对 v4 schema 的扩展见 `2.1 user_word_progress`，扩展字段需要同步到 `数据库与语料系统设计-v4执行版.md`。当前扩展字段为 `streakCorrect`。

它基于现有云端数据结构：

```text
words
wordbooks
wordbook_words
user_word_progress
user_book_progress
```

核心结论：

```text
每日学习负责引入新词。
答错词当天应该再次出现。
错题不需要单独存一份词表，优先由 user_word_progress 查询得到。
复习由 nextReviewAt 调度。
长期记录细粒度答题历史时，再追加 study_events。
```

## 1. 目标

学习系统要解决四件事：

```text
1. 每天给用户稳定数量的新词。
2. 用户答错后，短时间内重新遇到这个词。
3. 用户答对后，不要一直重复打扰。
4. 用户过几天回来时，能看到该复习的词。
```

MVP 不追求复杂算法，先做一个可解释、可调参、数据能迁移的机制。

## 2. 当前数据使用方式

### 2.1 user_word_progress

每个用户对每个单词一条记录。

```js
{
  _id: "openid_xxx:word_accurate",
  userId: "openid_xxx",
  accountId: "openid_xxx",
  wordId: "word_accurate",
  word: "accurate",
  normalized: "accurate",

  bookId: "ielts",
  lastReviewedBookId: "ielts",

  status: "new | learning | reviewing | mastered | difficult",
  lastResult: "known | unknown",

  correctCount: 2,
  wrongCount: 1,
  streakCorrect: 1,

  easiness: 2.4,
  interval: 1440,
  nextReviewAt: 1760000000000,

  lastReviewedAt: serverDate,
  clientUpdatedAt: 1760000000000,
  createdAt: serverDate,
  updatedAt: serverDate
}
```

现阶段已经有的字段：

```text
easiness
interval
nextReviewAt
correctCount
wrongCount
status
lastResult
clientUpdatedAt
```

建议补充字段：

```text
streakCorrect
```

它表示连续答对次数。`correctCount` 是历史总答对，`streakCorrect` 更适合判断是否掌握。

### 2.2 错题不是新集合

错题本优先不要单独建 `wrong_words` 集合。

原因：

```text
错题本本质是 user_word_progress 的筛选结果。
如果单独存 wrong_words，会产生两份状态：progress 里错了，wrong_words 里也错了，后面容易不同步。
```

错题查询：

```text
where userId = 当前用户
and wrongCount > 0
order by wrongCount desc
```

或者：

```text
where userId = 当前用户
and status = "difficult"
```

## 3. 每日学习流程

### 3.1 每日目标

用户可以设置：

```text
dailyGoal: 10 | 15 | 20 | 30
```

这个字段建议存在 `users.settings.dailyGoal`。

本地可以缓存一份，但云端是最终来源。

### 3.2 每日词池组成

每日学习不应该只抽新词，推荐按比例混合：

```text
70% 新词
20% 到期复习词
10% 高频错题
```

如果用户设置每日 10 个：

```text
新词 7 个
到期复习 2 个
错题 1 个
```

如果某一类不足，用新词补齐。

MVP 可以先简化为：

```text
先取到期复习词
再取当天错题
最后用新词补齐 dailyGoal
```

### 3.3 新词选择规则

按当前词书顺序取用户没有学过的词：

```text
wordbook_words where bookId = activeBookId
order by order asc
排除 user_word_progress 已存在的 wordId
```

这样用户每天看到的词是稳定的，不会随机跳。

## 4. 单次答题反馈

当前学习页是“看英文，选四个中文释义”。

答题结果建议只保留两类：

```text
known   答对
unknown 答错
```

`vague` 暂时不需要，因为选择题天然只有对错。以后如果做“认识 / 模糊 / 不认识”的自评卡片，再恢复 `vague`。

## 5. 答对逻辑

答对后：

```text
correctCount += 1
streakCorrect += 1
lastResult = "known"
```

根据连续答对次数安排下次复习：

```text
第 1 次答对 -> 1 天后复习
第 2 次连续答对 -> 3 天后复习
第 3 次连续答对 -> 7 天后复习
第 4 次连续答对 -> 15 天后复习
第 5 次连续答对 -> 30 天后复习，并标记 mastered
```

状态更新：

```text
streakCorrect < 5 -> status = "reviewing"
streakCorrect >= 5 -> status = "mastered"
```

是否继续出现在当天学习流：

```text
答对后当天不再出现。
```

这能降低挫败感，也让用户觉得自己在推进。

## 6. 答错逻辑

答错后：

```text
wrongCount += 1
streakCorrect = 0
lastResult = "unknown"
status = wrongCount >= 3 ? "difficult" : "learning"
```

错词应该进入两个队列：

```text
1. 当天重试队列
2. 长期复习队列
```

### 6.1 当天重试

答错后不要立刻下一题又出现同一个词，建议延迟 3-5 题后重新出现。

规则：

```text
wrongRetryQueue.push({
  wordId,
  availableAfterIndex: 当前题号 + 3
})
```

学习流取下一题时：

```text
如果 wrongRetryQueue 里有 availableAfterIndex <= 当前题号 的词，优先插入。
否则继续普通新词 / 复习词。
```

体验上会是：

```text
第 3 题答错 accurate
第 4-6 题做别的
第 7 题 accurate 再出现
```

### 6.2 当天重试上限

同一个词一天最多重试 2 次。

原因：

```text
一直错一直出现会烦。
错两次仍不会，应该进入错题复习，而不是当天硬磨。
```

字段可以先存在本地 session 内：

```js
todayWrongRetryCount: {
  word_accurate: 2
}
```

不用急着入库。

### 6.3 长期复习

答错后不再单独生成短期时间型复习点：

```text
答错 -> 不增加今日完成数
答错 -> 当前学习 session 内延迟若干题后重试
答错 -> 保留原 nextReviewAt，不写入短期时间型复习点
累计错 3 次及以上 -> status = difficult
```

也就是说，错题恢复只由当前学习队列负责：

```text
第 11 题答错时，今日进度仍保持 10/30。
该词会插入后续队列重试；只有达到今日通过条件后，进度才变为 11/30。
```

长期复习时间只在答对时推进：

```text
known -> 根据连续正确次数写入 1 / 3 / 7 / 15 / 30 天后的 nextReviewAt
unknown -> wrongCount + 1，streakCorrect 归零，nextReviewAt 保留旧值
```

## 7. 复习页逻辑

复习页只读 `user_word_progress`：

```text
where userId = 当前用户
and nextReviewAt <= now
and status != "mastered"
order by nextReviewAt asc
limit 50
```

## 7.1 跨天未完成队列

每日学习 session 按日期保存，因此新的一天不会直接恢复昨天的页面状态。但昨天未完成的词不能丢弃，新的 daily 队列应按以下顺序生成：

```text
1. 最近一个历史 daily session 中未通过的词
2. 已到期复习词
3. 新词 / 学习中词
```

队列总量使用用户设置的 `settings.dailyGoal`，不是固定数字。比如用户目标是 30，昨天剩 8 个未完成，则今天队列优先放入这 8 个，再补 22 个复习词或新词。答错词在通过前不增加今日完成数。

复习页不按词书顺序，而按到期时间排序。

如果同一个单词属于多本词书：

```text
复习仍然只出现一次，因为 user_word_progress 按 userId + wordId 共享。
```

如果 UI 需要展示来源：

```text
使用 lastReviewedBookId 显示“来自 IELTS”
或者反查 wordbook_words 显示“出现在 IELTS / CET4”
```

## 8. 错题本逻辑

错题本是一个视图，不是独立词库。

### 8.1 默认错题本

查询：

```text
where userId = 当前用户
and wrongCount > 0
order by wrongCount desc
limit 100
```

展示字段：

```text
word
translation
wrongCount
lastResult
nextReviewAt
status
```

### 8.2 难词本

难词是错题的子集：

```text
status = "difficult"
```

进入条件：

```text
wrongCount >= 3
```

退出条件：

```text
连续答对 3 次 -> status = "reviewing"
连续答对 5 次 -> status = "mastered"
```

## 9. 学习完成页

学习完成时不要直接把 DOM 消失，应该保留一个完成面板：

```text
今日完成 10 / 10
答对 8
答错 2
需要复习 2
连续学习 3 天
```

可提供三个动作：

```text
继续复习错题
再学 5 个
回首页
```

这比“页面空掉”更有反馈感。

## 10. 推荐状态机

```text
new
  -> 第一次进入每日学习

learning
  -> 新词阶段，答错或答对次数不足

reviewing
  -> 已经答对过，等待间隔复习

difficult
  -> 多次答错，需要重点复习

mastered
  -> 连续多次答对，暂时不进入日常复习
```

状态迁移：

```text
new + 答对 -> reviewing
new + 答错 -> learning

learning + 答对 -> reviewing
learning + 答错且 wrongCount >= 3 -> difficult

reviewing + 答对且 streakCorrect >= 5 -> mastered
reviewing + 答错 -> learning 或 difficult

difficult + 连续答对 3 次 -> reviewing
difficult + 连续答对 5 次 -> mastered
```

## 11. 是否需要 study_events

MVP 不需要。

等以后要做这些功能时再加：

```text
学习曲线
每天答题数统计
每个词的完整答题历史
AI 分析用户薄弱项
A/B 测试学习算法
```

再创建：

```text
study_events
```

示例：

```js
{
  _id: "event_xxx",
  userId: "openid_xxx",
  wordId: "word_accurate",
  bookId: "ielts",
  sessionId: "session_xxx",
  result: "known",
  mode: "daily",
  answer: "准确的",
  correctAnswer: "准确的；精确的",
  durationMs: 3200,
  createdAt: serverDate
}
```

现阶段只维护 `user_word_progress` 就够。

## 12. 推荐 MVP 实现顺序

### 第一步：补齐进度字段

在 `user_word_progress` 写入时补：

```text
streakCorrect
```

答对：

```text
streakCorrect += 1
```

答错：

```text
streakCorrect = 0
```

### 第二步：学习页当天错题重试

在页面内维护：

```text
wrongRetryQueue
todayWrongRetryCount
```

答错后延迟 3 题重新插入。

这一步主要改善学习体验，不一定要新建数据库字段。

### 第三步：复习页改成云端到期查询

从 `user_word_progress` 查：

```text
nextReviewAt <= now
status != mastered
```

不要每次本地扫全词书。

### 第四步：错题本页面

从 `user_word_progress` 查：

```text
wrongCount > 0
```

展示用户最常错的词。

### 第五步：users.settings.dailyGoal 云端持久化

每日目标从 `users.settings.dailyGoal` 读取，用户修改后写云端。

本地缓存只是加速，不作为最终数据源。

## 13. 当前建议采用的简单算法

为了先跑通产品，推荐第一版用这个：

### 答对

```js
streakCorrect += 1;
correctCount += 1;

const intervals = [1, 3, 7, 15, 30]; // 天
const day = intervals[Math.min(streakCorrect - 1, intervals.length - 1)];

nextReviewAt = now + day * 24 * 60 * 60 * 1000;
status = streakCorrect >= 5 ? "mastered" : "reviewing";
```

### 答错

```js
wrongCount += 1;
streakCorrect = 0;

// 答错只影响当前 session 的错题回炉，不生成短期时间型复习点。
// 如果这个词原本已经到期，保留原 nextReviewAt；如果是新词，nextReviewAt 继续为空。
nextReviewAt = previousNextReviewAt || 0;
status = wrongCount >= 3 ? "difficult" : "learning";
```

错题会在当前学习队列中延迟若干题后重试；答错时不增加今日完成数。

### 当天重试

```js
if (todayRetryCount[wordId] < 2) {
  wrongRetryQueue.push({
    wordId,
    availableAfterIndex: currentIndex + 3
  });
}
```

## 14. 最终结论

第一版建议这样做：

```text
1. user_word_progress 是唯一学习进度源。
2. 错题本不单独建表，只按 wrongCount / status 查询。
3. 答错当天延迟 3 题重试，最多重试 2 次。
4. 答错不生成短期时间型复习点，只保留原 nextReviewAt。
5. 答对按 1 / 3 / 7 / 15 / 30 天复习。
6. 连续答对 5 次标记 mastered。
7. 以后需要学习历史和统计时，再加 study_events。
```

这套机制足够轻，但已经能支撑：

```text
每日学习
到期复习
错题本
难词本
跨词书共享进度
未来迁移到独立 App / Web
```
