# 学习系统测试用例

更新时间：2026-07-16

本文档用于验收小程序的每日学习、复习、学习恢复和多端同步。测试结果栏由执行人填写；涉及云端状态的用例应在 `learn-submit` 部署后执行。

## 1. 测试约定

### 1.1 测试账号与数据

| 标识 | 用途 | 建议准备的数据 |
| --- | --- | --- |
| A | 全新用户 | 无 `user_word_progress`、无 `user_learn_sessions` |
| B | 普通学习用户 | 当日目标 5；至少 10 个未学习词 |
| C | 有复习任务的用户 | 25 个 `nextReviewAt <= 当前上海日期`，其中包含 1 个 `mastered` 和 1 个 `ignored` |
| D | 跨天未完成用户 | 昨天留下 2 个未完成的新词；今天目标 5 |
| E | 多端同步用户 | 同一微信账号登录设备 1、设备 2；当天有至少 5 个待学词 |

为避免本地缓存影响结果，每个用例开始前应注明：词书、账号、设备、是否清空本地缓存、当前上海日期。除非用例要求，不要清空云端进度。

### 1.2 验收口径

- 每日队列：先进入最多 20 个到期复习词，再进入昨天未完成的新词，最后补当天新词。
- 每日进度：只统计新词和跨天未完成新词；同轮注入的复习词不增加“今日新学”计数。
- 独立复习：展示所有到期词，不受每日 20 个上限影响。
- 单词被答错后必须按恢复规则再次出现，完成恢复后才算本轮通过。
- 忽略词不进入每日或复习队列；已掌握词不作为到期复习词出现。
- 多端合并时，不能丢失任一端已答题、已通过组和待恢复状态。

| ID | 前置条件 | 步骤 | 预期结果 | 结果 |

## 9. 建议执行顺序

1. 先执行 C-01，确认云函数已是本次版本。
2. 执行 L-01 至 L-09、Q-01 至 Q-08，确认单端主流程。
3. 执行 R-01 至 R-05，覆盖跨天和网络恢复。
4. 使用两台真机执行 M-01 至 M-05。
5. 最后执行 D-01 至 D-05 和 C-02 至 C-04，完成发布前回归。
