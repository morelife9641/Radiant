# 学习状态、收藏删除与复习机制 v2

本文档整理下一版学习系统设计，重点解决三个问题：

```text
1. 答对很多次才算 mastered 过重，用户体验不自然。
2. learn/detail 页面需要收藏、删除单词。
3. 复习机制需要更明确地贴近艾宾浩斯遗忘曲线，但保持 MVP 可实现。
```

## 1. 核心结论

推荐把“认识”和“掌握”拆开，但不要为“已认识”新增独立状态。

```text
已认识:
展示口径，由 correctCount > 0 表达。

复习中 reviewing:
用户认识，但还没经过足够时间验证，需要按间隔复习。

已掌握 mastered:
用户经过若干轮间隔复习仍然答对，可以降低出现频率。
```

不要再用“连续答对 5 次”作为 mastered 的门槛。这个门槛太高，用户会觉得明明认识还一直不算掌握。MVP 选择 `streakCorrect >= 3` 作为 mastered 门槛，后续可以通过配置调整。

推荐规则：

```text
首次答对 -> status = "reviewing"，1 天后复习，correctCount > 0 表示已认识
复习连续答对 2 次 -> status = "reviewing"，3 天后复习
复习连续答对 3 次 -> status = "mastered"，15 天后低频复习
答错 -> status = "learning" 或 "difficult"，短间隔重试
```

## 2. 数据结构调整

只需要扩展 `user_word_progress`，不用改 `words / wordbooks / wordbook_words`。

原因：

```text
words 是公共词典数据。
wordbook_words 是词书归属数据。
收藏、删除、掌握状态都是用户行为，只属于 user_word_progress。
```

### 2.1 user_word_progress

建议结构：

```js
{
  _id: "openid_xxx:word_accuracy",
  userId: "openid_xxx",
  accountId: "openid_xxx",

  bookId: "ielts",
  lastReviewedBookId: "ielts",
  wordId: "word_accuracy",
  word: "accuracy",
  normalized: "accuracy",

  status: "new | learning | reviewing | difficult | mastered | ignored",
  lastResult: "known | unknown",

  correctCount: 1,
  wrongCount: 0,
  streakCorrect: 1,

  easiness: 2.5,
  interval: 1440,
  nextReviewAt: 1760000000000,

  favorite: false,
  favoritedAt: null,

  ignoredAt: null,

  lastReviewedAt: 1760000000000,
  clientUpdatedAt: 1760000000000,
  createdAt: serverDate,
  updatedAt: serverDate
}
```

新增字段：

```text
favorite
favoritedAt
ignoredAt
```

新增状态：

```text
ignored
```

`ignoredAt` 只在 `status = "ignored"` 时有值。不要同时存 `ignored: true` 这种 boolean，避免和 `status` 产生重复状态。

已认识不进入 status 枚举，由以下条件表达：

```text
correctCount > 0
```

`mastered` 表示长期稳定掌握，不等同于“认识”。

## 3. 收藏功能

收藏是用户对单词的标记，不影响 SRS。

点击收藏：

```js
favorite = true
favoritedAt = Date.now()
```

取消收藏：

```js
favorite = false
favoritedAt = null
```

查询收藏夹：

```text
where userId = 当前用户
and favorite = true
order by favoritedAt desc
```

### 3.1 learn/detail 同步

learn 页面和 detail 页面都展示收藏状态，操作同一条 `user_word_progress`。

如果在 learn 页面收藏：

```text
当前卡片立即变更 UI。
云端异步保存。
进入 detail 页面时读取同一状态。
```

如果在 detail 页面收藏：

```text
返回 learn 页面时刷新当前词状态，保持按钮一致。
```

### 3.2 弱网与并发

收藏/取消收藏属于高频轻操作，推荐使用乐观 UI：

```text
1. 用户点击后，本地 UI 立即变化。
2. 本地写入 progress 缓存。
3. 500ms debounce 后只提交最新状态。
4. 请求携带 clientUpdatedAt。
5. 云端只接受 clientUpdatedAt 更新的写入。
```

如果云端保存失败：

```text
UI 不立即回滚，避免闪烁。
把操作写入 pendingActions 本地队列。
下次启动或下次进入 learn/detail 时重试。
```

这样可以避免用户连续点“收藏 -> 取消 -> 收藏”时，旧请求后返回覆盖新状态。

## 4. 删除功能

这里的“删除”不是真的删除公共单词，也不删除词书关系。

它应该表示：

```text
用户不想再学这个词。
```

推荐写入：

```js
ignoredAt = Date.now()
status = "ignored"
```

恢复：

```js
ignoredAt = null
status = correctCount > 0 ? "reviewing" : "learning"
```

### 4.1 删除后的行为

learn 页面：

```text
1. 当前词立刻从本轮学习队列移除。
2. 不算答对。
3. 不推进今日学习进度。
4. 不进入 review。
5. 跳到下一题。
```

删除流程必须走单独的 `updateWordState` action，不调用答题提交 `submit`，也不更新 `correctCount / wrongCount / streakCorrect`。

删除后不补新词进入今日池。也就是说，如果用户每日目标是 10，删除 1 个词后，本轮可以按 9/9 完成；这样实现最简单，也避免删除行为变成“换一个词继续塞满”。

review 页面：

```text
删除后从复习队列移除。
```

detail 页面：

```text
普通进入 detail：按钮显示“恢复”。
从 learn 进入 detail：删除后返回 learn 并进入下一题。
```

### 4.2 取词过滤

每日学习取词时过滤：

```text
status !== "ignored"
```

复习取词时同样过滤：

```text
nextReviewAt <= now
and status !== "mastered"
and status !== "ignored"
```

## 5. mastered 机制调整

旧规则：

```text
streakCorrect >= 5 -> mastered
```

问题：

```text
用户已经认识，但系统迟迟不承认。
首页/词书页如果显示“已掌握”，长期为 0，反馈差。
连续 5 次答对需要很多天，MVP 阶段太重。
```

推荐新规则：

```text
第 1 次答对:
  status = "reviewing"
  interval = 1 天
  nextReviewAt = now + 1 天

第 2 次连续答对:
  status = "reviewing"
  interval = 3 天
  nextReviewAt = now + 3 天

第 3 次连续答对:
  status = "mastered"
  interval = 15 天
  nextReviewAt = now + 15 天
```

如果希望稍微严格一点：

```text
streakCorrect >= 3 且 correctCount >= 3 -> mastered
```

这比 5 次自然很多，也仍然保留长期验证。

## 6. 与艾宾浩斯遗忘曲线的关系

艾宾浩斯遗忘曲线的核心不是固定公式，而是：

```text
刚学完遗忘最快，所以早复习。
复习成功后，下一次间隔可以变长。
答错说明记忆强度不足，要缩短间隔。
```

MVP 不需要精确拟合遗忘率公式，可以采用“间隔递增 + 答错重置”的 SRS。

### 6.1 推荐间隔

首次答对后的长期复习间隔：

```text
第 1 次答对: 1 天
第 2 次连续答对: 3 天
第 3 次连续答对: 15 天，并标记 mastered
mastered 后: 15 天低频复习
```

答错后的重试：

```text
第 1 次答错: 当天延迟 3 题后重试，不增加今日完成数
第 2 次答错: 继续留在当前 session 的后续队列中重试
第 3 次及以上: status = "difficult"
unknown 不写入短期时间型 nextReviewAt，保留原 nextReviewAt
```

这种规则贴近艾宾浩斯的实践含义：

```text
短期错词在当前学习队列内高频出现。
答对词逐步拉长间隔。
稳定答对后降低打扰。
```

### 6.2 easiness 的使用

当前 `easiness` 字段可以保留，但 MVP 阶段不读也不写。

原因：

```text
当前复习间隔使用固定规则 1 / 3 / 15。
如果写入 easiness 但不参与 nextReviewAt 计算，字段没有实际价值。
等未来引入 SM-2 或动态间隔算法，再启用 easiness。
```

未来可以用 `easiness` 动态调整间隔：

```text
nextInterval = baseInterval * easiness
```

当前阶段推荐固定间隔，避免调参过早。

## 7. 首页和词书页显示口径

不要把主进度叫“已掌握”。

推荐展示：

```text
已认识: correctCount > 0
已掌握: status = "mastered"
待复习: nextReviewAt <= now 且 status not in ["ignored", "mastered"]
已删除: status = "ignored"
```

首页主卡：

```text
今日: todayKnown / dailyGoal
词书: knownCount / totalWords
待复习: reviewCount
```

词书列表：

```text
已认识 42/3610
```

如果要显示 mastered，建议作为次级指标，不作为主进度：

```text
长期掌握 8
```

## 8. learn 页面按钮设计

learn 卡片增加两个操作：

```text
收藏
删除
```

推荐位置：

```text
单词卡右上角放两个轻量 icon button。
收藏：星标或书签。
删除：划掉/隐藏图标。
```

交互：

```text
收藏:
  不影响当前答题。
  即时更新按钮状态。

删除:
  弹二次确认可以先不做。
  当前词立即跳过。
  不算答对，不推进今日进度。
  调用 updateWordState，不调用 submit。
```

如果担心误删：

```text
删除后 toast: 已移除，可在设置/词书中恢复
```

## 9. detail 页面按钮设计

detail 页面同步展示：

```text
收藏 / 已收藏
删除 / 恢复
```

从 learn 进入 detail 时：

```text
收藏后留在 detail。
删除后返回 learn，并让 learn 进入下一题。
```

普通从搜索或词书进入 detail 时：

```text
删除后留在 detail，按钮变为“恢复”。
```

## 10. 云函数接口建议

云函数接口以 `数据库与语料系统设计-v4执行版.md` 的 `learn-submit` 契约为准。

本机制文档只规定行为：

```text
答题提交 -> action: submit
收藏 / 删除 / 恢复 -> action: updateWordState
```

`updateWordState` 不更新 `correctCount / wrongCount / streakCorrect`，也不推进今日学习进度。具体输入、输出、必填字段、`clientUpdatedAt` 幂等规则见 v4 执行版 `8.2 learn-submit / action: updateWordState`。

## 11. 索引建议

`user_word_progress` 当前已有：

```text
idx_user_word: userId + wordId unique
idx_user_next_review: userId + nextReviewAt
idx_user_wrong: userId + wrongCount
```

建议新增：

```text
idx_user_favorite: userId + favorite + favoritedAt
```

`idx_user_status` 已在 v4 §9 中列出，不重复建。MVP 如果暂时不做收藏列表，可以先不建 `idx_user_favorite`。

## 12. 实施顺序

推荐按这个顺序做：

```text
1. 扩展 user_word_progress 字段: favorite / favoritedAt / ignoredAt。
2. 修改 SRS: mastered 从 streakCorrect >= 5 改成 >= 3。
3. 修改首页和词书页文案: “已掌握”改成“已认识”。
4. learn 页面增加收藏/删除按钮。
5. detail 页面同步收藏/删除按钮。
6. learn-submit 增加 updateWordState action。
7. 学习/复习取词过滤 status = "ignored"。
8. 根据需要补索引。
```

## 13. 待确认问题

```text
1. 删除是否需要二次确认？
2. mastered 后是否完全不出现，还是 15 天后低频复习？
```

建议 MVP 选择：

```text
删除不二次确认，但 toast 提醒。
搜索/detail 中允许恢复。
mastered 后 15 天低频复习。
首页主进度叫“已认识”。
```
