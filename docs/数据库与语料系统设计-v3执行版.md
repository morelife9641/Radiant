# 数据库与语料系统设计 v3 执行版

本文档是当前阶段的执行版，合并了 `数据库与语料系统设计.md` 以及两轮 review 的有效建议。后续建库、写导入脚本、改云函数，以本文档为准。

## 1. 当前要建的集合

第一阶段手动创建 10 个集合：

```text
users
words
wordbooks
wordbook_words
user_word_progress
user_book_progress
content_topics
content_lines
content_line_words
app_config
```

暂不创建：

```text
study_events
study_sessions
user_preferences
```

原因：

- `study_events` / `study_sessions` 等要做学习报告、数据分析时再建。
- `user_preferences` 先不单独建，MVP 直接放 `users.preferredTopicIds`。

## 2. 核心原则

```text
单词只存一份。
词书只是单词集合关系。
主题语料和词书分开。
用户单词进度按 userId + wordId 共享。
用户词书进度按 userId + bookId 聚合。
用户 preference 决定单词详情优先展示哪些主题例句。
```

Valorant 有两种可能身份：

```text
Valorant 主题语料 -> content_topics / content_lines
Valorant 高频术语词书 -> wordbooks / wordbook_words
```

不要把主题语料混进词书。

## 3. 集合结构

### 3.1 users

```js
{
  _id: "openid_xxx",
  openid: "openid_xxx",
  accountId: "openid_xxx",
  nickname: "同学",
  avatarUrl: "",
  purpose: "exam",
  activeBookId: "ielts",
  preferredTopicIds: ["valorant"],
  settings: {
    dailyGoal: 10,
    accent: "us",
    autoPlayWordAudio: false,
    detailExampleMode: "preferred_first"
  },
  stats: {
    streakDays: 0,
    lastCheckInDate: "",
    totalLearned: 0
  },
  localMigration: {
    progressMigratedAt: null
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

说明：

- `_id = openid`。
- `accountId` 先等于 `openid`，以后做 App / Web 时映射成全平台用户 ID。
- 不在 `users` 内重复存 `userId`。
- 其他业务集合里的 `userId` 第一阶段使用 `openid`。

### 3.2 words

全局单词实体库，一个单词或短语只存一份。

```js
{
  _id: "word_accurate",
  word: "accurate",
  normalized: "accurate",
  type: "word",
  phonetic: {
    uk: "/ˈækjərət/",
    us: "/ˈækjərət/",
    default: "/ˈækjərət/"
  },
  audio: {
    us: "",
    uk: ""
  },
  audioPolicy: null,
  senses: [
    {
      pos: "a",
      translation: "正确无误的；精确的",
      definitionEn: "",
      definitionZh: "",
      collinsEn: "",
      collinsZh: "",
      synonyms: [],
      antonyms: [],
      gamingLink: null
    }
  ],
  contextStats: {
    totalLines: 0,
    byTopic: {}
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

`audioPolicy` 默认 `null`，只用于覆盖默认音频拼接规则，比如特殊文件名、私有桶或签名 URL。

CET4 v2 字段映射：

```text
collins_definition.en -> senses[].collinsEn
collins_definition.zh -> senses[].collinsZh
synonyms[].nuance_explanation -> senses[].synonyms[].nuanceEn
synonyms[].example_en -> senses[].synonyms[].exampleEn
synonyms[].example_zh -> senses[].synonyms[].exampleZh
antonyms -> senses[].antonyms
gaming_link -> senses[].gamingLink
```

同形异义词策略：

```text
MVP 一词一记录。
lead / bank 暂不拆多条 word。
多个义项放 senses[]。
```

```js
  id: "ielts",
  name: "雅思核心词",
  category: "exam",
  cefrLevel: "B2",
  totalWords: 3610,
  description: "雅思核心词汇",
  cover: {
    letter: "I",

  },
  status: "published",
  schemaVersion: 1,
  contentVersion: 1,
  source: {
    name: "IELTS Word List.txt",
    importedAt: 1779700000000
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

版本语义：

```text
schemaVersion:
  数据结构版本。schema 变化才升级。

contentVersion:
  内容修订版本。词条增删改、释义更新时升级。
```

客户端缓存失效只看 `contentVersion`。

### 3.4 wordbook_words

词书和单词的关系表。

```js
{
  _id: "ielts_word_accurate",
  bookId: "ielts",
  wordId: "word_accurate",
  word: "accurate",
  normalized: "accurate",
  order: 123,
  chapter: "Word List 02",
  important: true,
  tags: [],
  bookSenseOverride: null,
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `_id = bookId + "_" + wordId`。
- 不用 `order` 做 `_id`，因为顺序可能重排。
- `important` / `tags` 属于词书内属性，写在这里，不写入 `words`。
- 如果 `tags === [bookId]`，可以不写 tags 或写空数组，减少冗余。
- `bookSenseOverride` 非空时整段替换 `words.senses`，不做 merge。
- 如果新版词书把 `bookSenseOverride` 从有值改为 `null`，导入脚本必须显式 set null。

### 3.5 user_word_progress

用户对单词的全局掌握状态，跨词书共享。

```js
{
  _id: "openid_xxx_word_accurate",
  userId: "openid_xxx",
  wordId: "word_accurate",
  normalized: "accurate",
  status: "learning",
  easiness: 2.5,
  interval: 1440,
  nextReviewAt: 1779786400000,
  correctCount: 2,
  wrongCount: 1,
  lastResult: "known",
  lastBookId: "ielts",
  firstSeenAt: 1779700000000,
  lastReviewedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

`status`：

```text
new
learning
reviewing
mastered
ignored
```

`lastBookId` 只记录最近一次在哪本词书学习，不参与进度判断。

### 3.6 user_book_progress

用户对某本词书的聚合进度。

```js
{
  _id: "openid_xxx_ielts",
  userId: "openid_xxx",
  bookId: "ielts",
  learnedCount: 120,
  masteredCount: 36,
  totalWords: 3610,
  todayDone: 6,
  lastReviewedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `learnedCount` 只统计用户在本书内实际学过的词。
- 用户在 IELTS 学过 `accurate`，不自动增加 TOEFL 的 `learnedCount`。
- 但用户打开 TOEFL 的 `accurate` 时，可以继承 `user_word_progress`。
- `dueCount` 不存，按 `user_word_progress.nextReviewAt <= now` 动态算。

`todayDone` 规则：

```text
读取时：
  如果 lastReviewedAt 不在今天，todayDone 视为 0。

写入时：
  如果 lastReviewedAt 不在今天，先清零再 +1。
  如果 lastReviewedAt 在今天，直接 +1。
```

### 3.8 content_lines

主题下的真实句子、台词、音频和出处。

```js
{
  _id: "line_valorant_8f3a21c9aa32",
  topicId: "valorant",
  text: "I am on a higher plane, chale, literally!",
  normalizedText: "i am on a higher plane chale literally",
  translationZh: "",
  audio: {
    fileName: "AstraPick.mp3",
    localPath: "audio/Astra/AstraPick.mp3",
    url: "https://static.wikia.nocookie.net/..."
  },
  speaker: {
    name: "Astra",
    type: "agent"
  },
  scene: {
    section: "Agent Selected/Unlocked",
    season: "",
    episode: "",
    timestampMs: null
  },
  source: {
    csvRow: 2,
    sourceFile: "valorant_quotes/lines.csv",
    sourceUrl: ""
  },
  tokenCount: 9,
  matchedWordCount: 0,
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

`content_lines._id` 统一规则：

```text
line_${topicId}_${stableHash}

stableHash = md5(
  text + "|" +
  speaker.name + "|" +
  (audio.fileName || "") + "|" +
  (scene.section || "") + "|" +
  (scene.timestampMs || "")
).slice(0, 12)
```

不要 hash 整个 `scene` 对象，避免 Python / JS 序列化顺序不一致。

`translationZh` 可先为空，后续用 AI 批量翻译入库并抽检。

## 4. normalize 与 tokenize

`normalized` 规则：

```js
normalized(s) = s.trim().toLowerCase()
```

MVP 不做这些事：

```text
不去标点
不合并内部空格
不替换连字符
不合并英美拼写
```

所以：

```text
easy-going !== easy going
favour !== favor
```

语料分词规则必须和 `normalized` 对齐：

```text
tokenize(text):
  1. 按空白和常规句读切分
  2. 保留英文撇号和连字符
  3. 每个 token 再执行 normalized(token)
```

示例：

```text
We're -> we're
easy-going -> easy-going
plane, -> plane
```

不要把 `we're` 拆成 `we` / `re`。

导入脚本和小程序运行时应共用同一套规则。建议后续新增：

```text
miniprogram/utils/normalize.js
scripts/normalize.py
```

## 5. 单词详情页 preference 查询

用户设置：

```js
users.preferredTopicIds = ["valorant"]
```

打开单词详情：

```text
1. 当前单词 normalized -> wordId
2. 读取 users.preferredTopicIds
3. 调用 topic-fetch.wordExamples
4. 云函数按 topic 逐个查询 content_line_words
5. 根据 lineId 查询 content_lines
6. 返回 primary / secondary / topics
```

不要直接查：

```text
topicId in preferredTopicIds AND wordId = X
```

微信云数据库里 `in` 与复合索引表现不可控。云函数按 topic 逐个查更稳。

`topic-fetch.wordExamples` 返回结构：

```js
{
  ok: true,
  primary: [
    {
      line: {},
      words: []
    }
  ],
  secondary: [],
  topics: [
    {
      id: "valorant",
      name: "Valorant",
      cover: {}
    }
  ]
}
```

同一 topic 内排序：

```text
1. audio.url 存在优先
2. speaker 尽量多样
3. lineId 稳定排序
```

```text

```

## 13. 词书更新与搜索

词书修订流程：

```text
导入新版词书
  -> 与现有 words / wordbook_words diff
  -> 新词 insert
  -> 修订释义 update words 或 bookSenseOverride
  -> 删除词标记 archived，不物理删除
  -> wordbooks.contentVersion + 1
```

客户端启动时比对 `wordbooks.contentVersion`，版本变化后失效本地词书缓存。

搜索建议走云函数：

```text
全局搜：
  words.normalized 前缀匹配

本书内搜：
  wordbook_words.normalized 前缀匹配 + bookId

主题台词搜：
  content_lines.normalizedText 前缀 / 包含匹配 + topicId
```

MVP 先做全局搜词即可。
