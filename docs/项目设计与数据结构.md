# 项目设计与数据结构

本文档梳理当前小程序的产品流程、代码模块、词书数据设计，以及后续接入云数据库后的推荐数据结构。

## 1. 当前产品流程

当前应用是一个本地优先的背单词小程序，主流程如下：

```text
首次进入
  -> 选择学习目的
  -> 选择词书
  -> 首页

日常使用
  -> 首页
  -> 今日学习 / 复习
  -> 单词卡片
  -> 认识 / 模糊 / 不认识
  -> 写入学习进度
  -> 回到首页查看进度
```

详情和发音流程：

```text
单词卡片
  -> 单词详情
  -> 查看音标、释义、同义词、例句

点击发音
  -> 根据 word 拼 COS CDN 地址
  -> wx.downloadFile
  -> statusCode === 200 时播放 tempFilePath
```

```js

```

目前词书是静态打包进小程序的：

```text
miniprogram/assets/data/wordbooks/cet4.js
miniprogram/assets/data/wordbooks/ielts.js
```

### 2.2 学习与复习

学习页：

```text
miniprogram/pages/learn/index.js
```

本地存储 key：

```text
onboarding.wordbook          当前词书
settings.dailyGoal           每日目标
today.${bookId}.${date}      当天学习词列表
progress.${bookId}           当前词书下的学习进度

```

当前进度结构：

```js
progress[word] = {
  easiness,
  interval,
  nextReviewAt,
  correctCount,
  wrongCount,
  status,
  _todayDone,
  updatedAt

```

### 2.3 发音

发音模块：

```text
miniprogram/utils/audio.js
```

当前规则：

```text
https://ielts-word-audio-1411800061.cos.ap-guangzhou.myqcloud.com/audio/{word}.mp3
```

播放流程：

```text
getWordAudioUrl(word)
  -> playWord(word)
  -> wx.downloadFile(url)
  -> playUrl(tempFilePath)
```

这样可以避免 403/404 的 XML 错误页被播放器当成 mp3 解码。

## 3. 当前词书数据结构

当前静态词书结构：

```js
module.exports = {
  wordbook: {
    id: 'ielts',
    name: '雅思核心词',
    category: 'exam',
    cefrLevel: 'B2',
    totalWords: 3610,
    source: 'IELTS Word List.txt',
    version: 1,
    schema: 'senses-v1'
  },
  words: [
    {
      word: 'abate',
      phonetic: '/əˈbeɪt/',
      senses: [
        {
          pos: 'v',
          translation: '减轻，减弱'
        }
      ],
      tags: ['ielts'],
      important: false,
      _id: 'ielts-0001',
      order: 1
    }
  ]
};
```

这个结构适合 MVP，因为读取简单、无网络依赖。但它有一个长期问题：同一个单词如果同时出现在 CET4、IELTS、TOEFL，会在多个词书文件里重复保存。

## 4. 推荐目标模型

长期设计应该把“单词”和“词书”拆开：

```text
words               单词实体库
wordbooks           词书元信息
wordbook_words      词书和单词的关联关系
users               用户信息
user_word_progress  用户对某个单词的掌握进度
user_book_progress  用户对某本词书的聚合进度
study_sessions      每次学习记录
```

核心原则：

```text
单词只存一份
词书只是单词集合
用户进度优先按 userId + wordId 记录
词书进度按 userId + bookId 做聚合
```

这样可以支持：

- 同一个单词被多个词书共享。
- 用户在 IELTS 学过 `accurate`，切到 TOEFL 时也能继承这个词的掌握状态。
- 不同词书可以有不同排序、重点标记、章节信息。
- 单词释义、音频、音标只维护一份。

## 5. 云数据库设计

以下以微信云数据库集合为例。

### 5.1 users

存用户基础信息和偏好。

```js
{
  _id: 'openid',
  openid: 'xxx',
  nickname: '同学',
  avatarUrl: '',
  purpose: 'exam',
  activeBookId: 'ielts',
  interests: ['dota2', 'valorant'],
  settings: {
    dailyGoal: 10,
    accent: 'us',
    autoPlay: false
  },
  stats: {
    streakDays: 3,
    lastCheckInDate: '2026-05-25',
    totalLearned: 120
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

建议 `_id` 直接用 `openid`，查询最简单。

### 5.2 words

单词实体库。一个英文单词或短语只存一份。

```js
{
  _id: 'word_accurate',
  word: 'accurate',
  normalized: 'accurate',
  type: 'word',
  phonetic: {
    uk: '/ˈækjərət/',
    us: '/ˈækjərət/'
  },
  audio: {
    us: 'https://.../audio/accurate.mp3',
    uk: ''
  },
  senses: [
    {
      pos: 'a',
      translation: '正确无误的；精确的',
      definitionEn: '',
      definitionZh: ''
    }
  ],
  exchange: {
    comparative: '',
    superlative: ''
  },
  sourceTags: ['ielts', 'cet4'],
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

字段说明：

- `normalized` 用于去重和查询，统一小写、trim。
- `word` 保留展示用原文。
- `type` 可选 `word`、`phrase`。
- `audio` 后续可以从固定 CDN 拼接，也可以存对象 URL。
- `sourceTags` 只是辅助，不代表词书关系，真正关系放在 `wordbook_words`。

### 5.3 wordbooks

词书元信息。

```js
{
  _id: 'ielts',
  id: 'ielts',
  name: '雅思核心词',
  category: 'exam',
  cefrLevel: 'B2',
  totalWords: 3610,
  description: '雅思核心词汇',
  cover: {
    letter: 'I',
    color: '#1A1A1A'
  },
  status: 'published',
  version: 1,
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

`status` 建议支持：

```text
draft
published
archived
```

这样未来可以在后台先导入词书，再发布给用户。

### 5.4 wordbook_words

词书和单词的关系表。重点设计点在这里。

```js
{
  _id: 'ielts_0001',
  bookId: 'ielts',
  wordId: 'word_emperor',
  word: 'emperor',
  order: 1,
  chapter: 'Word List 01',
  important: false,
  tags: ['ielts'],
  bookSenseOverride: null,
  createdAt: 1779700000000
}
```

为什么需要这个集合：

- `emperor` 可以同时属于 IELTS、CET6、TOEFL。
- 每本词书里的顺序不同，所以 `order` 不能放在 `words`。
- 每本词书的重点标记不同，所以 `important` 也不应该只放在 `words`。
- 某些词书可能有自己的中文释义，可以放 `bookSenseOverride`。

查询一本词书时：

```text
按 bookId 查询 wordbook_words
按 order 排序
拿到 wordId 列表
批量查询 words
合并返回
```

小程序端最终拿到的仍然可以是当前页面熟悉的结构：

```js
{
  word: 'emperor',
  phonetic: '/ˈempərə(r)/',
  senses: [...],
  order: 1,
  important: false
}
```

### 5.5 user_word_progress

用户对“单词实体”的掌握进度。推荐按 `userId + wordId` 唯一。

```js
{
  _id: 'openid_word_accurate',
  userId: 'openid',
  wordId: 'word_accurate',
  normalized: 'accurate',
  status: 'learning',
  easiness: 2.5,
  interval: 1440,
  nextReviewAt: 1779786400000,
  correctCount: 2,
  wrongCount: 1,
  lastResult: 'known',
  lastBookId: 'ielts',
  firstSeenAt: 1779700000000,
  lastReviewedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

`status` 建议：

```text
new
learning
reviewing
mastered
ignored
```

这里按 `wordId` 管进度，而不是按 `bookId + wordId` 管进度，是为了实现“单词跨词书共享进度”。

例子：

```text
用户在 IELTS 学过 accurate
  -> user_word_progress 记录 word_accurate = learning

用户切到 TOEFL
  -> TOEFL 里也有 accurate
  -> 直接读取同一条 user_word_progress
  -> 不需要从零学习
```

### 5.6 user_book_progress

用户对某本词书的聚合进度。这个集合不是必须，但很有用，可以减少首页统计成本。

```js
{
  _id: 'openid_ielts',
  userId: 'openid',
  bookId: 'ielts',
  learnedCount: 120,
  masteredCount: 36,
  dueCount: 8,
  todayDone: 6,
  totalWords: 3610,
  lastStudiedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

这个集合可以由 `learn-submit` 云函数在每次提交答案后更新。

### 5.7 study_sessions

记录一次学习会话，用于复盘、统计、排查问题。

```js
{
  _id: 'session_xxx',
  userId: 'openid',
  bookId: 'ielts',
  mode: 'daily',
  startedAt: 1779700000000,
  endedAt: 1779700300000,
  total: 10,
  known: 6,
  vague: 3,
  unknown: 1,
  wordIds: ['word_emperor', 'word_exact']
}
```

MVP 可以先不做这个集合，等要做学习报告时再加。

### 5.8 study_events

如果未来要做更细的行为分析，可以记录每次答题事件。

```js
{
  _id: 'event_xxx',
  userId: 'openid',
  bookId: 'ielts',
  wordId: 'word_accurate',
  result: 'known',
  mode: 'daily',
  answeredAt: 1779700000000,
  responseTimeMs: 2500
}
```

这个集合量会比较大，不建议 MVP 一开始就写，除非明确要做数据分析。

## 6. 云函数职责设计

### 6.1 user-sync

职责：

```text
获取 OPENID
创建或更新 users
返回用户档案和当前词书
```

输入：

```js
{
  profilePatch: {
    nickname,
    purpose,
    activeBookId,
    settings
  }
}
```

输出：

```js
{
  ok: true,
  user: {}
}
```

### 6.2 wordbook-fetch

职责：

```text
拉取词书列表
拉取某本词书的单词
```

接口：

```text
action=list
action=detail
```

`detail` 建议支持分页：

```js
{
  action: 'detail',
  id: 'ielts',
  limit: 100,
  cursor: 0
}
```

小程序端可以先缓存整本，也可以按章节/分页加载。

### 6.3 learn-submit

职责：

```text
生成今日学习词
提交答题结果
更新 user_word_progress
更新 user_book_progress
```

提交输入：

```js
{
  action: 'submit',
  bookId: 'ielts',
  wordId: 'word_accurate',
  result: 'known'
}
```

云函数内部计算 SRS，不建议完全相信前端传来的 `nextReviewAt`。

### 6.4 audio

当前音频是公开 COS CDN，不一定需要云函数。

如果未来要做私有桶或签名 URL，可以新增：

```text
cloudfunctions/audio-url
```

职责：

```text
接收 wordId / word
返回临时签名 URL
```

## 7. 用户进度如何跨词书共享

推荐逻辑：

```text
学习进度按 wordId 存
词书进度按 bookId 聚合
```

答题时：

```text
用户在 IELTS 回答 accurate
  -> 找到 wordId = word_accurate
  -> 更新 user_word_progress(openid, word_accurate)
  -> 同步更新 user_book_progress(openid, ielts)
```

切换词书时：

```text
用户切换到 TOEFL
  -> 拉取 TOEFL 的 wordId 列表
  -> 批量查 user_word_progress
  -> 已学过的词直接带入状态
```

首页统计时：

```text
优先读 user_book_progress
如果没有聚合记录，再临时计算
```

这种方式比 `progress.${bookId}.${word}` 更合理，因为后者会导致同一个词在不同词书里重复学习。

## 8. 推荐索引

微信云数据库建议建这些索引：

```text
words
  normalized 唯一索引

wordbooks
  category + status

wordbook_words
  bookId + order
  bookId + wordId
  wordId

user_word_progress
  userId + wordId 唯一索引
  userId + nextReviewAt
  userId + status

user_book_progress
  userId + bookId 唯一索引
```

## 9. 迁移路线

### 阶段 1：继续本地静态词书

当前已完成：

```text
CET4 静态词书
IELTS 静态词书
本地学习进度
COS CDN 发音
```

适合继续验证学习体验。

### 阶段 2：进度云同步

先不要动词书结构，只把本地 `progress.${bookId}` 同步到云端。

最小实现：

```text
learn-submit 写 user_word_progress
home 读取云端统计
本地 storage 作为离线缓存
```

### 阶段 3：词书云端化

把静态词书拆成：

```text
words
wordbooks
wordbook_words
```

小程序端仍然保留 `wordbook-loader` 作为统一接口，只是底层从 `require()` 变成云函数拉取。

### 阶段 4：内容增强

后续可以加：

```text
例句
同义词辨析
AI 助记
错词本
掌握词列表
学习报告
```

这些都应围绕 `wordId` 扩展，不要再围绕某个词书内的临时 `_id` 扩展。

## 10. 当前需要注意的问题

1. 当前 `progress.${bookId}` 是按词书隔离的，本地阶段可以接受，但云端阶段应改成按 `wordId` 共享。
2. 当前 IELTS 词书里有短语，如 `roll film`、`in addition to`。音频 CDN 如果没有对应文件，会提示“音频不可访问”。
3. 当前音频文件名按 `word.toLowerCase()` 拼接，短语会变成带空格的 URL 编码。如果 CDN 文件名不是这种规则，需要在 `audio.js` 增加文件名映射。
4. 静态词书继续增加会占小程序包体，TOEFL/GRE 加入后建议云端按需加载。
5. 云函数里计算 SRS 更可靠，前端只负责展示和提交用户选择。
