# 数据库与语料系统设计 v4 执行版

本文档是当前阶段最新执行版，替代 v3。它吸收了 v3 review 中确实影响实现的建议，并明确哪些规则以后写导入脚本、云函数、前端 service 时必须遵守。

## 1. 本轮 review 判断

必须采纳：

- `wordbook_words.tags` 规则和导入映射冲突：采纳，v4 删除 `tags` 字段，后续确有二级标签再加。
- 东八区日期函数不够稳：采纳，改用 `Intl.DateTimeFormat`，并要求补测试用例。
- unique 索引时机：采纳，导入前先建必要 unique 索引。
- `wordbook-fetch` 输出契约缺失：采纳，补接口返回结构。
- `app_config` 启动兜底缺失：采纳，补硬编码默认值 + 异步刷新。
- `bulkImport`、`contentVersion`、`stableHash`、`tokenize` 等 v3 已采纳规则继续保留。

部分采纳：

- `_id` 长度问题：采纳分隔符建议，使用 `openid:wordId`，但不依赖 `_id` 反解析，查询仍靠 `userId + wordId` 索引。
- `wordId + bookId` 反向查询：保留 `wordId` 单字段索引即可，MVP 不额外建组合索引。
- `contextStats`：保留，但明确由导入脚本维护，运行时不更新。
- `id` 冗余：采纳，`wordbooks` 和 `content_topics` 只用 `_id`，不再重复存 `id`。

暂不采纳或后置：

- `source.csvRow` 改 `source.locator`：可读性上有道理，但现阶段 Valorant CSV 是主要来源；v4 保留 `csvRow`，同时增加可选 `locator`。
- 立刻处理 CET4 音频桶：这是资源治理问题，不影响数据库结构。v4 在音频策略里注明短期 CET4 可能 404，长期补 `words.audio` 或换桶。
- 错误码 / 日志规范：采纳为轻量约定，不展开成完整观测体系。

## 2. 第一阶段要建的集合

手动创建 10 个集合：

```text
users
words
wordbooks

user_word_progress

```

暂不创建：

```text
study_events

```

## 3. 核心模型

```text
users
  用户、设置、偏好、迁移标记

words
  全局单词实体，一个单词只存一份

wordbooks
  词书元信息

wordbook_words
  词书和单词的关系，保存 order / chapter / important

content_topics
  Valorant / Dota / 美剧等主题

content_lines
  主题下的真实台词、例句、音频、出处

content_line_words
  台词命中了哪些 words

user_word_progress
  用户对某个 word 的全局掌握状态，跨词书共享

user_book_progress
  用户对某本词书的聚合进度

app_config
  数据源开关和灰度回滚配置
```

Valorant 主题语料和 Valorant 词书是两种东西：

```text
Valorant 主题语料 -> content_topics / content_lines
Valorant 高频术语词书 -> wordbooks / wordbook_words
```

不要混表。

## 4. 集合结构

### 4.1 users

```js
{
  _id: "openid_xxx",
  openid: "openid_xxx",
  accountId: "openid_xxx",
  nickname: "同学",
  avatarUrl: "",
  purpose: "exam",
  activeBookId: "ielts",
  preferredTopicIds: ["valorant"],
  settings: {
    dailyGoal: 10,
    accent: "us",
    autoPlayWordAudio: false,
    detailExampleMode: "preferred_first"
  },
  stats: {
    streakDays: 0,
    lastCheckInDate: "2026-05-26",
    totalLearned: 0
  },
  localMigration: {
    progressMigratedAt: null
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `_id = openid`。
- `accountId` 先等于 `openid`，以后做 App / Web 时映射为全平台用户 ID。
- `stats.lastCheckInDate` 是东八区 `YYYY-MM-DD` 字符串，不用 timestamp。
- `stats.totalLearned = count(user_word_progress where userId)`，同一个 `wordId` 跨词书只算一次。
- 不在 `users` 内重复存 `userId`。

### 4.2 words

```js
{
  _id: "word_accurate",
  word: "accurate",
  normalized: "accurate",
  type: "word",
  phonetic: {
    uk: "/ˈækjərət/",
    us: "/ˈækjərət/",
    default: "/ˈækjərət/"
  },
  audio: {
    us: "",
    uk: ""
  },
  audioPolicy: null,
  senses: [
    {
      pos: "a",
      translation: "正确无误的；精确的",
      definitionEn: "",
      definitionZh: "",
      collinsEn: "",
      collinsZh: "",
      synonyms: [],
      antonyms: [],
      gamingLink: null
    }
  ],
  contextStats: {
    totalLines: 0,
    byTopic: {}
  },
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `audioPolicy` 默认 `null`，只用于覆盖默认音频拼接规则。
- `contextStats` 由 `build_content_line_words.py` 写入，运行时不更新。
- 同形异义词 MVP 不拆表，多个义项放 `senses[]`。

`audioPolicy` 可为 `null`。非空时结构如下：

```js
{
  provider: "rule", // "rule" | "url" | "signed"
  baseUrl: "",
  fileName: "",
  signFunctionName: ""
}
```

含义：

```text
provider=rule:
  使用 baseUrl + "/" + encodeURIComponent(fileName)

provider=url:
  直接使用 words.audio.us / words.audio.uk

provider=signed:
  调用 signFunctionName 获取临时播放 URL
```

默认拼接规则：

```text
fileName = encodeURIComponent(words.normalized) + ".mp3"
url = DEFAULT_WORD_AUDIO_BASE_URL + "/" + fileName
```

短语如 `roll film` 默认会生成 `roll%20film.mp3`。如果实际 CDN 文件名不同，必须写 `audioPolicy.fileName` 或直接写 `words.audio`。

CET4 v2 映射：

```text
collins_definition.en -> senses[].collinsEn
collins_definition.zh -> senses[].collinsZh
synonyms[].nuance_explanation -> senses[].synonyms[].nuanceEn
synonyms[].example_en -> senses[].synonyms[].exampleEn
synonyms[].example_zh -> senses[].synonyms[].exampleZh
antonyms -> senses[].antonyms
gaming_link -> senses[].gamingLink
```

缺失字段默认：

```text
phonetic 缺失 -> ""
senses 扩展字段缺失 -> "" / [] / null
important 缺失 -> false
```

- `schemaVersion` 是数据结构版本，schema 变化才升级。

### 4.4 wordbook_words

```js
{
  _id: "ielts:word_accurate",
  bookId: "ielts",
  wordId: "word_accurate",
  word: "accurate",
  normalized: "accurate",
  order: 123,
  chapter: "Word List 02",
  important: true,
  bookSenseOverride: null,
  createdAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `_id = bookId + ":" + wordId`。
- 不使用 `order` 做 `_id`，顺序可能重排。
- `important` 是词书内属性，写在这里。
- v4 删除 `tags` 字段。当前 IELTS 的 `tags: ["ielts"]` 与 `bookId` 重复，信息密度低。未来如果确实需要二级标签，再新增 `labels` 或 `tags`。
- `bookSenseOverride` 非空时整段替换 `words.senses`。
- 如果新版词书把 `bookSenseOverride` 改回 `null`，导入脚本必须显式 set null。

导入映射：

```text
word.word / phonetic / senses -> words
word.important / order / chapter -> wordbook_words
word.tags 不导入
```

### 4.5 user_word_progress

```js
{
  _id: "openid_xxx:word_accurate",
  userId: "openid_xxx",
  wordId: "word_accurate",
  normalized: "accurate",
  status: "reviewing",
  easiness: 2.5,
  interval: 1440,
  nextReviewAt: 1779786400000,
  correctCount: 2,
  wrongCount: 1,
  streakCorrect: 1,
  lastResult: "known",
  favorite: false,
  favoritedAt: null,
  ignoredAt: null,
  lastReviewedBookId: "ielts",
  firstSeenAt: 1779700000000,
  lastReviewedAt: 1779700000000,
  clientUpdatedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `_id = userId + ":" + wordId`。
- 不依赖 `_id` 反解析，查询使用 `userId + wordId` 索引。
- `lastReviewedBookId` 只记录最近在哪本词书学习，不参与进度判断。
- `status` 枚举值：`new` / `learning` / `reviewing` / `difficult` / `mastered` / `ignored`。
- `lastResult` 枚举值：`known` / `unknown`。选择题模式只有对错；`vague` 留给未来自评卡片，不进入当前 v4 正式 schema。
- `streakCorrect` 表示连续答对次数，答错时重置为 0，用于判断是否进入 `mastered`。
- `favorite` / `favoritedAt` 表示用户收藏状态，不影响 SRS。
- `ignoredAt` 只在 `status = "ignored"` 时有值；不额外保存 `ignored: true`，避免和 `status` 重复。
- “已认识”不是 status 枚举，用 `correctCount > 0` 表达。
- `clientUpdatedAt` 是客户端提交进度时的毫秒时间戳，用于本地缓存与云端数据合并；`updatedAt` 使用服务端时间。

### 4.6 user_book_progress

```js
{
  _id: "openid_xxx:ielts",
  userId: "openid_xxx",
  bookId: "ielts",
  learnedCount: 120,
  masteredCount: 36,
  totalWords: 3610,
  todayDone: 6,
  lastReviewedAt: 1779700000000,
  updatedAt: 1779700000000
}
```

规则：

- `learnedCount` 只统计用户在本书内实际学过的词。
- `masteredCount = count(user_word_progress where userId AND wordId in this book AND status = "mastered")`。
- 用户在 IELTS 学过 `accurate`，不自动增加 TOEFL 的 `learnedCount`。
- TOEFL 打开 `accurate` 时可继承 `user_word_progress`。
- `dueCount` 不存，按 `user_word_progress.nextReviewAt <= now` 动态算。

`todayDone`：

```text
读取时：
  如果 lastReviewedAt 不在今天，todayDone 视为 0。

写入时：
  如果 lastReviewedAt 不在今天，先清零再 +1。
  如果 lastReviewedAt 在今天，直接 +1。
```

### 4.10 app_config

```js
{
  _id: "default",
  wordbookDataSource: "local",
  progressDataSource: "local",
  topicDataSource: "cloud",
  configVersion: 1,
  updatedAt: 1779700000000
}
```

启动策略：

```text
1. 前端硬编码默认配置，local 优先。
2. 启动后异步拉 app_config。
3. 拉取失败时继续使用硬编码默认值或本地缓存。
4. configVersion 变化时刷新本地缓存。
```

客户端缓存逻辑：

```text
1. 读取 wx.getStorageSync('app_config.cached')。
2. 若无缓存，使用 utils/config.js 内的硬编码默认值。
3. 异步拉远程 app_config/default。
4. 若 remote.configVersion > cached.configVersion，则用 remote 覆盖并写入本地。
5. 若拉取失败，继续使用当前本地配置。
```

`app_config/default` 由管理端手动创建一次，后续只 update，不 insert 多条配置。

配置变更默认下次启动生效：当前进程写入本地缓存后不强制重载已渲染页面，避免学习流程中途切换数据源。

## 5. 冗余字段说明

以下字段是查询辅助或展示快照，不是 source of truth：

```text
wordbook_words.word
wordbook_words.normalized
user_word_progress.normalized
content_line_words.normalized
content_line_words.surface
```

权威数据在：

```text
words.word / words.normalized
content_lines.text
```

`user_word_progress.normalized` 保留的理由：当客户端或迁移脚本只有原始 `word` 字符串、暂时不知道 `wordId` 时，可用于排查和兜底反查。常规查询仍使用 `userId + wordId`。

## 6. normalize 与 tokenize

`normalized`：

```js
normalized(s) = s.trim().toLowerCase()
```

MVP 不做：

```text
不去标点
不合并内部空格
不替换连字符
不合并英美拼写
```

语料分词必须与 `normalized` 对齐：

```text
tokenize(text):
  1. 按空白和常规句读切分
  2. 保留英文撇号和连字符
  3. 每个 token 再执行 normalized(token)
```

推荐正则：

```js
text.split(/[\s,;.!?:()"“”—–]+/).filter(Boolean)
```

注意：正则不要切 `'` 和 `-`。

示例：

```text
We're -> we're
easy-going -> easy-going
plane, -> plane
```

不要把 `we're` 拆成 `we` / `re`。

## 7. 日期规则

所有业务日期 key 用东八区 `YYYY-MM-DD`。

小程序实现：

```js
function getDateKeyAsiaShanghai(date = new Date()) {
  return new Intl.DateTimeFormat('en-CA', {
    timeZone: 'Asia/Shanghai',
    year: 'numeric',
    month: '2-digit',
    day: '2-digit'
  }).format(date);
}
```

必须补测试用例：

```text
UTC 2026-05-25 15:30 -> Asia/Shanghai 2026-05-25
UTC 2026-05-25 16:30 -> Asia/Shanghai 2026-05-26
UTC 2026-05-25 23:30 -> Asia/Shanghai 2026-05-26
```

学习复习里的“明天 09:00”也按 Asia/Shanghai 计算：

```js
function getTomorrowAtNineAsiaShanghai(now = new Date()) {
  const parts = new Intl.DateTimeFormat('en-CA', {
    timeZone: 'Asia/Shanghai',
    year: 'numeric',
    month: '2-digit',
    day: '2-digit'
  }).formatToParts(now);

  const get = (type) => Number(parts.find(part => part.type === type).value);
  return Date.UTC(get('year'), get('month') - 1, get('day') + 1, 1, 0, 0);
}
```

说明：

```text
Asia/Shanghai 明天 09:00 等于 UTC 明天 01:00。
返回值为毫秒时间戳，用于 nextReviewAt。
```

### 8.1 wordbook-fetch

词书列表输入：

```js
{
  action: "list",
  category: "exam"
}
```

MVP 词书列表不分页，按 `createdAt asc` 返回。未来词书数超过 100 时再给 list 增加分页。

词书列表输出：

```js
{
  ok: true,
  items: [
    {
      bookId: "ielts",
      name: "雅思核心词",
      category: "exam",
      cefrLevel: "B2",
      totalWords: 3610,
      cover: {},
      contentVersion: 1
    }
  ]
}
```

词书详情输入：

```js
{
  action: "detail",
  bookId: "ielts",
  cursor: "",
  limit: 50
}
```

输出：

```js
{
  ok: true,
  total: 3610,
  cursor: "next_cursor_or_empty",
  items: [
    {
      wordId: "word_accurate",
      word: "accurate",
      normalized: "accurate",
      phonetic: {
        default: "/ˈækjərət/"
      },
      senses: [],
      order: 123,
      chapter: "Word List 02",
      important: true,
      audio: {},
      audioPolicy: null
    }
  ]
}
```

cursor 规则：

```text
首次请求传空字符串。
cursor = base64(JSON.stringify({ lastOrder: 123, lastWordId: "word_accurate" }))
返回空字符串表示没有更多。
```

分页排序按 `order asc, wordId asc`。下一页查询从 `order > lastOrder OR (order == lastOrder AND wordId > lastWordId)` 开始，避免 order 相等时漏词或重复。

字段来源：

```text
wordId / order / chapter / important:
  来自 wordbook_words

word / normalized:
  优先使用 wordbook_words 快照字段；如缺失则使用 words

phonetic / audio / audioPolicy:
  来自 words

senses:
  bookSenseOverride 非空 -> 使用 wordbook_words.bookSenseOverride
  否则 -> 使用 words.senses
```

`senses` 取值：

```text
bookSenseOverride 非空 -> 使用 bookSenseOverride
否则 -> 使用 words.senses
```

### 8.2 learn-submit

`learn-submit` 负责学习流、复习流、错题查询和进度写入。

#### action: today

每日学习取词。

输入：

```js
{
  action: "today",
  bookId: "ielts",
  dailyGoal: 10
}
```

取词规则：

```text
1. 先取 user_word_progress 中到期复习词：
   userId = 当前用户
   nextReviewAt <= now
   status not in ["mastered", "ignored"]

2. 再取高频错题：
   userId = 当前用户
   wrongCount > 0
   status not in ["mastered", "ignored"]
   order by wrongCount desc

3. 最后用当前词书的新词补齐 dailyGoal：
   wordbook_words where bookId = activeBookId
   order by order asc
   排除用户已存在 user_word_progress 的 wordId
```

MVP 比例：

```text
到期复习优先。
错题最多占 dailyGoal 的 10%-20%。
剩余位置用新词补齐。
```

输出：

```js
{
  ok: true,
  bookId: "ielts",
  dailyGoal: 10,
  items: [
    {
      wordId: "word_accurate",
      word: "accurate",
      normalized: "accurate",
```

## 9. 索引

导入前先建必要 unique 索引：

```text
words.normalized unique
wordbook_words.bookId + wordId unique
user_word_progress.userId + wordId unique
user_book_progress.userId + bookId unique
```

导入完成后再建非 unique 索引：

```text
wordbooks.category + status
wordbooks.status

wordbook_words.bookId + order
wordbook_words.wordId

user_word_progress.userId + nextReviewAt
user_word_progress.userId + status
user_word_progress.userId + favorite + bookIds + favoritedAt + wordId

user_learning_activity.userId + wordbookId + dateKey
user_learning_activity.userId + dateKey

content_topics.status
content_topics.type + status

content_lines.topicId
content_lines.topicId + speaker.name
content_lines.topicId + scene.section

content_line_words.wordId + topicId
content_line_words.lineId
```

数据一致性：

```text
content_topics.stats
words.contextStats
```

都由导入 / 重建脚本维护。后续如果手工增删 `content_lines`，需要运行 `check_data_consistency.py` 或重建脚本校验并重算。

说明：

- `wordbook_words.wordId` 用于反查一个词出现在哪些词书。
- MVP 不建 `wordId + bookId` 组合索引；需要更复杂反查时再加。

## 13. 更新与搜索

词书修订流程：

```text
导入新版词书
  -> 与现有 words / wordbook_words diff
  -> 新词 insert
  -> 修订释义 update words 或 bookSenseOverride
  -> 删除词标记 archived，不物理删除
  -> 全部写入成功后，wordbooks.contentVersion + 1
```

客户端启动时比对 `wordbooks.contentVersion`，版本变化后失效本地词书缓存。

`contentVersion` 由导入脚本在所有写入完成后一次性递增；单条 update 不单独触发版本递增。

搜索走云函数：

```text
全局搜：
  words.normalized 前缀匹配

本书内搜：
  wordbook_words.normalized 前缀匹配 + bookId

主题台词搜：
  content_lines.normalizedText 前缀 / 包含匹配 + topicId
```

MVP 先做全局搜词。

搜索限制：

```text
前缀匹配 limit 20。
微信云数据库 regex 不适合大表全文搜索。
content_lines.normalizedText 全文搜需要 ES / 自建倒排，MVP 不做。
```
