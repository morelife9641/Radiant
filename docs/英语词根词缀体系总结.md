# 英语词根词缀体系总结

这份文档用于后续设计单词详情页里的「词根词缀拆解」模块。核心目标不是把词源学做成百科，而是让用户看到一个单词时，能更快理解它为什么是这个意思。

先区分三类东西：

- `prefix` 前缀：放在词前，常改变方向、否定、程度、数量、时间等含义，如 `im-`, `re-`, `trans-`。
- `suffix` 后缀：放在词后，常改变词性或语法功能，如 `-tion`, `-able`, `-ly`。
- `root/base` 词根/词基：承载核心语义，如 `spec/spect` = 看，`port` = 携带，`plic` = 折叠。

注意：`spec` 这种不是前缀，而是词根。产品上可以统一叫「词根词缀拆解」，但数据结构里最好分开维护。

## 1. 最重要的原则

### 1.1 不要按字符串硬拆

看到 `im-` 不一定就是“不”。比如：

| 单词 | 拆解 | `im-` 的意思 |
|---|---|---|
| `impersonal` | im- + personal | 不，非 |
| `impossible` | im- + possible | 不，非 |
| `implicit` | im- + plic | 在内，向内 |
| `import` | im- + port | 进入，向内 |
| `implant` | im- + plant | 进入，植入 |
| `impose` | im- + pos/pose | 放到上面，施加 |

所以 `im-` 至少要拆成两个不同的 morpheme：

- `im-` negative：不，非。
- `im-` inward：在内，进入，向内，放到……上。

它们拼写一样，但词源和语义不同。

### 1.2 同化不是重点，判断才是重点

很多拉丁/希腊前缀会因为后面字母不同而改变拼写，这叫同化。比如 `in-` 后面接 `p / b / m` 时，为了发音顺，会变成 `im-`。

但对学生来说，真正有用的不是背“同化”这个术语，而是知道：

```text
看到 im + xxx，不要马上翻译成“不”。
先问：xxx 像不像一个独立形容词？
```

最实用的初判：

| 看到的结构 | 大概率含义 | 例子 | 考场怎么猜 |
|---|---|---|---|
| `im + 独立形容词` | 不，非 | `impossible`, `impersonal`, `imperfect` | 先按反义猜 |
| `im + 动作/位置词根` | 进入，在内，放到上面 | `import`, `implant`, `implicit`, `impose` | 先按方向/位置猜 |
| `im + 看不懂的词基` | 严格拆词不强拆，但可以做助记联想 | `improve` | 阅读回到上下文，记忆可以用联想 |

所以 `impersonal` 不是因为 `im-` 天生等于“不”，而是因为 `personal` 本身是一个清楚的形容词，“im + personal” 很自然就是“not personal”。

`implicit` 不一样。后面不是一个现代英语里常见的独立形容词 `plicit`，而是词根 `plic`，意思是“折叠”。这时 `im-` 更像 `in / into`，“折在里面”，所以是“隐含的”。

### 1.3 一个词可以有「结构解释」和「助记解释」

这个模块的核心目标是帮助学生理解和记忆，不是做词源学审判。所以同一个词可以分两层：

| 类型 | 用途 | 要求 | 例子 |
|---|---|---|---|
| 结构解释 | 帮学生理解词义来源 | 尽量接近真实词源/构词 | `implicit` = im- 在内 + plic 折叠 |
| 助记解释 | 帮学生记住单词 | 可以是联想，但要合理、不离谱 | `improve` 可联想为“向内证明自己，所以提升” |

以前文档里说 `improve` 不建议展示，是站在“严格词源解释”的角度。但如果站在学生记忆角度，它可以展示为助记解释：

```text
improve
助记：im- 可以联想到 inward / 向内，prove 是证明。
可以想成“向内证明自己，让自己变得更好”。
=> 提高，改善
```

这种解释不需要声称它是严格词源，只要在数据里标记为 `mnemonic`，前端展示成“记忆法”即可。

### 1.4 考场使用词根词缀的真实目标

词根词缀不是让学生在考场上“精确翻译单词”，而是帮学生快速判断词义方向。

阅读里最有用的是这四类判断：

| 判断目标 | 你要猜什么 | 例子 |
|---|---|---|
| 正负方向 | 是正面还是负面，是肯定还是否定 | `impossible`, `illegal`, `unfair` |
| 空间方向 | 是进入、出去、穿过、在下、在上 | `import`, `export`, `transmit`, `submarine` |
| 动作核心 | 是看、说、写、带、放、转、折 | `inspect`, `predict`, `transport`, `implicit` |
| 词性功能 | 是名词、形容词、动词还是副词 | `development`, `visible`, `modernize`, `quickly` |

学生不需要在第一眼就知道 `implicit` 的完整中文释义。只要能猜到：

```text
im- 可能是 in
plic 可能是 fold
=> something folded inside
=> 这个词大概率和“隐藏、内含、没直接说出来”有关
```

这就已经足够帮助理解文章。

反过来，如果一个词拆完以后完全解释不通，阅读时不要继续纠结。词根词缀是辅助工具，不是万能解码器。但在背词场景里，可以给一个温和的助记联想，只要不把它包装成严格词源即可。

## 2. `im-` 专题：考场怎么判断

`im-` 最容易误导学生，因为它不是固定等于“不”。遇到 `im + xxx`，不要先背词源，先做一个阅读理解里的快速判断。

### 2.1 三步判断法

```text
第一步：挡住 im-，看后面剩下的部分。
第二步：如果后面是你认识的形容词，优先猜“不/非”。
第三步：如果后面更像动作词根，优先猜“进入/在内/放上”。
```

最简单的口诀：

```text
im + adjective = not adjective
im + action/root = in / into / on + root
```

| 单词 | 挡住 `im-` 后 | 判断 | 考场粗猜 |
|---|---|---|---|
| `impossible` | `possible` 是形容词 | 否定 | 不可能的 |
| `impersonal` | `personal` 是形容词 | 否定 | 非个人的，客观的 |
| `imperfect` | `perfect` 是形容词 | 否定 | 不完美的 |
| `immoral` | `moral` 是形容词 | 否定 | 不道德的 |
| `import` | `port` 是“携带”词根 | 方向 | 带进来，进口 |
| `implant` | `plant` 是种植/放置动作 | 方向 | 种进去，植入 |
| `implicit` | `plic` 是“折叠”词根 | 方向 | 折在里面，隐含的 |
| `impose` | `pos/pose` 是“放置”词根 | 位置 | 放到上面，施加 |

这个规则不是为了做词源考试，而是为了让你在阅读里遇到陌生词时，能先猜出方向。

### 2.2 什么时候 `im-` 大概率是“不”

如果 `im-` 后面是一个可以独立出现的形容词，先按否定猜。

| 单词 | 后面部分 | 为什么按否定猜 |
|---|---|---|
| `impossible` | `possible` = 可能的 | `not possible` 很通顺 |
| `impersonal` | `personal` = 个人的 | `not personal` 很通顺 |
| `imperfect` | `perfect` = 完美的 | `not perfect` 很通顺 |
| `immoral` | `moral` = 道德的 | `not moral` 很通顺 |
| `impolite` | `polite` = 礼貌的 | `not polite` 很通顺 |
| `impatient` | `patient` = 耐心的 | `not patient` 很通顺 |
| `impractical` | `practical` = 实际的 | `not practical` 很通顺 |
| `impartial` | `partial` = 偏袒的，片面的 | `not partial`，所以是公正的 |

判断信号：

- 后面是完整形容词：`possible`, `personal`, `perfect`, `moral`, `patient`。
- 直接翻译成 `not + 后面部分` 很顺。
- 整词通常还是形容词。

考场例子：

```text
The report should be impersonal.
```

你不认识 `impersonal` 也没关系：

```text
im + personal
personal = 个人的
im = not
=> not personal
=> 不带个人色彩的，客观的
```

### 2.3 什么时候 `im-` 大概率是“进入/在内/放上”

如果 `im-` 后面不是一个常见独立形容词，而是一个动作词根或位置词根，先按 `in / into / on` 猜。

| 单词 | 后面部分 | 词根感觉 | 考场粗猜 |
|---|---|---|---|
| `import` | `port` | carry，携带 | carry in，带进来 |
| `implant` | `plant` | plant，种植/放置 | plant into，植入 |
| `immerse` | `mers` | sink/dip，沉入 | put into liquid，沉浸 |
| `implicit` | `plic` | fold，折叠 | folded in，隐含的 |
| `imply` | `ply/plic` | fold，折叠 | 意思折在里面，暗示 |
| `impose` | `pos/pose` | put，放置 | put on/upon，施加 |
| `imprison` | `prison` | prison，监狱 | put into prison，监禁 |
| `imprint` | `print` | print，印 | press/print into，印上 |

判断信号：

- 后面不是完整形容词，或者你不能自然说 `not + 后面部分`。
- 后面像动作：携带、种植、放置、折叠、沉入、印上。
- 整词常是动词或由动作引申来的形容词/名词。

`implicit` 的理解过程：

```text
implicit
不是 im + plicit，因为 plicit 不是常见独立形容词。
更合理的是 im + plic。
im = in / into / 在内
plic = fold / 折叠
=> folded in
=> 意思被折在里面
=> 隐含的
```

### 2.4 最容易混的对照

| 单词 | 错误猜法 | 正确思路 |
|---|---|---|
| `impersonal` | im = 进入，所以进入个人 | `personal` 是形容词，所以 `im-` = not |
| `implicit` | im = 不，所以不 plicit | `plicit` 不是常见独立词，`plic` 是折叠词根，所以 `im-` = in |
| `import` | im = 不，所以不 port | `port` 是携带词根，所以 `im-` = into |
| `imperfect` | im = 进入，所以进入完美 | `perfect` 是形容词，所以 `im-` = not |

### 2.5 快速分叉图

```text
看到 im + xxx
       |
       v
xxx 是完整形容词吗？
       |
   是  |  否
       |
       v
先猜 not xxx       xxx 像动作/位置词根吗？
                         |
                     是  |  否
                         |
                         v
                  先猜 in/into/on + xxx
                         |
                         v
                    还不通？回到上下文
```

### 2.6 练习：按规则猜

| 单词 | 判断过程 | 大概意思 |
|---|---|---|
| `impatient` | `patient` 是形容词，先猜 `not patient` | 不耐心的 |
| `impractical` | `practical` 是形容词，先猜 `not practical` | 不实际的 |
| `impartial` | `partial` 是形容词，先猜 `not partial` | 不偏袒的，公正的 |
| `impure` | `pure` 是形容词，先猜 `not pure` | 不纯的 |
| `imprison` | `prison` 是地点名词，像 `put into prison` | 监禁 |
| `imprint` | `print` 是动作，像 `print into/on` | 印上，留下印记 |
| `imbue` | 后面不透明，别硬拆 | 结合语境猜“灌输，使充满” |

这些主要改变语法形式，不改变核心词义：

| 后缀 | 作用 | 例子 |
|---|---|---|
| `-s / -es` | 复数或第三人称单数 | `books`, `goes` |
| `-ed` | 过去式/过去分词 | `worked`, `played` |
| `-ing` | 现在分词/动名词 | `working`, `learning` |
| `-er / -est` | 比较级/最高级 | `faster`, `fastest` |

## 7. 判断一个词怎么拆

建议按这个顺序：

1. 先去掉透明的后缀：如 `development` 先看 `develop + -ment`。
2. 再看前缀家族：如 `impossible` 可能是 `im-`，但要判断是哪一个 `im-`。
3. 找词根/词基：如 `implicit` 里的 `plic` = fold。
4. 用整词含义校验：拆出来的含义必须能解释整词。
5. 不透明就不展示：宁可少展示，也不要误导。

例子：

| 单词 | 推荐拆解 | 不推荐 |
|---|---|---|
| `implicit` | im- 在内 + plic 折叠 | im- 不 + plicit |
| `impersonal` | im- 不 + personal 个人的 | im- 进入 + personal |
| `respect` | re- 回头/再次 + spect 看 | res + pect |
| `transport` | trans- 穿过 + port 携带 | tran + sport |

## 8. 产品数据结构建议

### 8.1 `word_morphemes`

维护词素本身。注意同形不同义要拆成不同记录。

```json
{
  "_id": "morpheme_im_negative",
  "text": "im-",
  "base": "in-",
  "type": "prefix",
  "family": "in_negative",
  "meaningZh": "不，非",
  "meaningEn": "not",
  "origin": "Latin",
  "allomorphOf": "morpheme_in_negative",
  "examples": ["impossible", "impersonal", "immoral"],
  "note": "in- 否定前缀在 m/p/b 前的同化形式。"
}
```

```json
{
  "_id": "morpheme_im_inward",
  "text": "im-",
  "base": "in-",
  "type": "prefix",
  "family": "in_inward",
  "meaningZh": "进入，在内，向内",
  "meaningEn": "in, into, on",
  "origin": "Latin",
  "allomorphOf": "morpheme_in_inward",
  "examples": ["import", "implant", "implicit", "impose"],
  "note": "与否定 im- 同形，但语义不同。"
}
```

词根也放在这里：

```json
{
  "_id": "morpheme_plic",
  "text": "plic",
  "type": "root",
  "family": "plic_fold",
  "meaningZh": "折叠",
  "meaningEn": "fold",
  "origin": "Latin",
  "examples": ["implicit", "complicate", "application"]
}
```

### 8.2 `word_morpheme_links`

维护某个单词如何拆解。建议单独建集合，避免把所有拆解都塞进 `words` 后导致文档越来越重。

```json
{
  "_id": "word_morph_implicit_v1",
  "wordId": "word_implicit",
  "word": "implicit",
  "explanationType": "structural",
  "items": [
    {
      "order": 1,
      "morphemeId": "morpheme_im_inward",
      "text": "im-",
      "role": "prefix",
      "meaningZh": "在内，隐含"
    },
    {
      "order": 2,
      "morphemeId": "morpheme_plic",
      "text": "plic",
      "role": "root",
      "meaningZh": "折叠"
    }
  ],
  "explainZh": "字面是“折在里面的”，引申为“隐含的，未明说的”。",
  "confidence": "high",
  "status": "published"
}
```

助记型解释也可以放在同一个集合里，但 `explanationType` 要标成 `mnemonic`：

```json
{
  "_id": "word_morph_improve_mnemonic_v1",
  "wordId": "word_improve",
  "word": "improve",
  "explanationType": "mnemonic",
  "items": [
    {
      "order": 1,
      "text": "im-",
      "role": "prefix_hint",
      "meaningZh": "可联想为向内、自我"
    },
    {
      "order": 2,
      "text": "prove",
      "role": "base_hint",
      "meaningZh": "证明"
    }
  ],
  "explainZh": "可以想成“向内证明自己，让自己变得更好”，所以是“提高，改善”。",
  "note": "这是助记解释，不作为严格词源。",
  "confidence": "mnemonic",
  "status": "published"
}
```

### 8.3 是否要回写到 `words`

可以在 `words` 里只缓存摘要：

```json
{
  "_id": "word_implicit",
  "word": "implicit",
  "morphemeSummary": {
    "hasMorphemes": true,
    "count": 2,
    "primaryExplainZh": "im- 在内 + plic 折叠"
  }
}
```

详情页再按 `wordId` 查 `word_morpheme_links`。这样后续改词根词缀解释，不需要大规模重导 `words`。

## 9. 前端展示建议

`implicit`：

```text
implicit
im- = in / into / 在内
plic = fold / 折叠
=> folded in / 含在里面的，隐含的
```

`impersonal`：

```text
impersonal
im- = not / 不，非
personal = personal / 个人的
=> not personal / 非个人的，客观的
```

展示层要避免两个问题：

- 不要把所有 `im-` 都展示成“不”。
- 不要把助记联想包装成严格词源。像 `improve` 这类词可以展示“记忆法”，但标签应写成助记，而不是词源拆解。

## 10. 落地优先级

建议分三步：

1. MVP：只做高透明、高收益词。比如 `implicit`, `import`, `impossible`, `transport`, `predict`, `respect`。
2. 第二阶段：建立 `word_morphemes` 和 `word_morpheme_links`，支持同形不同义和同化家族。
3. 第三阶段：把词根词缀和学习题型结合，出「根据词根猜词义」「同前缀词群」「同词根词群」等题。

## 11. 总结

- 前缀、后缀、词根要分开建模，但前端可以统一展示为「词根词缀拆解」。
- `im-` 这类同形多义必须拆成不同记录：`im- = 不` 和 `im- = 在内/进入` 不是一回事。
- 同化形式要归家族，比如 `in- / im- / il- / ir-`。
- 最好以 `word_morpheme_links` 维护单词拆解，而不是只在 `words` 里塞字符串。
- MVP 阶段优先展示透明、可解释、能帮助记忆的词，避免过度词源化。
